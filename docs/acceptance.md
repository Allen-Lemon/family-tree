# 端到端验收说明

## 1. 验收环境与证据

在与生产等价的隔离环境执行，记录版本/提交、镜像 digest、执行人、日期、浏览器和结果。每项保存截图、API 响应、审计记录或日志片段；不得在证据中暴露密码、令牌或真实敏感信息。测试数据使用虚构人物。

## 2. 项目与配置

- [ ] 项目根目录精确命名 `family-tree`；根目录包含 README、`.gitignore`、`.env.example`；
- [ ] `.env.example` 只有占位符，无真实秘密；`.env` 被 Git 忽略；
- [ ] `deploy/`、`docs/`、`scripts/` 文件齐全；Dockerfile 位于 deploy 且 context 为项目根；
- [ ] `bootstrap-check.ps1` 在缺 Docker、缺 `.env`、包含 `CHANGE_ME`、目录名错误时给出明确失败；
- [ ] 脚本和 Compose 不硬编码真实密码或 API Key。

## 3. 构建与启动

- [ ] 从干净环境运行 `Copy-Item .env.example .env`，填写占位符后检查通过；
- [ ] `start.ps1` 可构建并启动 MySQL 8.4、backend、frontend/Nginx；
- [ ] MySQL、backend、frontend 均进入 healthy；依赖顺序正确；
- [ ] MySQL 使用 utf8mb4，中文姓名及生平可完整写入/读取；
- [ ] MySQL 数据和上传文件在容器重建后仍存在；
- [ ] MySQL 无宿主机端口，backend 只绑定 127.0.0.1，Nginx 提供页面与 `/api/` 代理；
- [ ] `stop.ps1` 默认保留卷；未显式确认时拒绝删除卷；
- [ ] Windows 中文路径、PowerShell 5.1 和 UTF-8 配置可工作；端口覆盖有效。

## 4. 认证与权限

- [ ] 空库首次启动根据 `ADMIN_USERNAME`、`ADMIN_PASSWORD`、`ADMIN_EMAIL` 创建管理员；非空库重启不覆盖密码；
- [ ] 管理员可以使用高强度初始密码登录；错误密码不泄露用户是否存在；登录限流与密码自助轮换列入后续安全加固；
- [ ] 会话超时、Cookie 安全属性、CSRF 防护和注销失效均符合契约；
- [ ] ADMIN、EDITOR、VIEWER 页面和接口权限一致；仅隐藏按钮不能绕过服务端授权；
- [ ] 普通用户不能访问其他无权限家谱、媒体、导出和审计；
- [ ] 无法删除/停用最后一名管理员；关键操作产生审计记录。

## 5. 家谱核心业务

- [ ] 创建、查询、修改、软删除家谱；列表分页、搜索和排序正确；
- [ ] 创建成员并维护姓名、曾用名、性别、生卒日期、生平、头像和隐私级别；
- [ ] 创建父母子女、配偶、收养和监护关系，树形页面正确展示；
- [ ] 后端拒绝自关联、重复关系、祖先循环、跨家谱关系和悬空 ID；
- [ ] 两个客户端同时编辑，旧 `version` 返回 409，不静默覆盖；
- [ ] 在世成员敏感字段按角色裁剪；删除含关系成员有明确冲突处理；
- [ ] 树深度和大数据量下有截断/分页机制，不一次返回无限节点。

## 6. 页面与 API 对齐

- [ ] `/login`、`/dashboard`、家谱列表/树、成员详情、媒体、导入、导出、OCR、用户与审计页面可达；
- [ ] API 统一为 `/api/v1`，JSON UTF-8、ISO 8601 时间、分页结构和错误结构符合 `api-contract.md`；
- [ ] 401、403、404、409、413、415、422、429 和 500 场景返回正确且无堆栈；
- [ ] 请求 ID 可关联代理、应用与审计日志；健康端点不暴露内部信息。

## 7. 文件与媒体安全

- [ ] 合法图片/附件上传、授权下载、元数据修改、软删除正常；
- [ ] 超过 `MAX_UPLOAD_SIZE_MB`、伪造 MIME、路径穿越文件名、危险扩展名被拒绝；
- [ ] 存储文件名由服务端生成，不能通过 URL 直接遍历 uploads；
- [ ] 启用 ClamAV profile 后服务 healthy，干净文件放行，EICAR 测试文件被隔离/拒绝；
- [ ] ClamAV 不可用或扫描错误时默认阻断；审计和日志不记录文件全文。

## 8. OCR

- [ ] 默认 `OCR_ENABLED=false`、`OCR_PROVIDER=disabled`；未配置密钥时系统不会向任何外部地址发请求；
- [ ] 禁用状态创建 OCR 任务返回 `OCR_DISABLED`，页面明确提示；
- [ ] 经批准启用本地/外部 Provider 后，任务状态、超时、限流重试、取消、幂等正常；
- [ ] OCR 返回页码、坐标和置信度；低置信度进入人工复核；
- [ ] OCR 结果不会未经确认直接覆盖成员权威字段；
- [ ] 日志不包含 API Key、原图或 OCR 全文，停用和密钥轮换流程有效。

## 9. 导入导出

- [ ] GEDCOM、CSV、JSON（及实现声明的 ZIP/XLSX）按模板预检、报告错误并提交；
- [ ] 损坏编码、悬空引用、关系循环、超限文件、压缩炸弹和 CSV 公式注入被处理；
- [ ] 导入失败无半成品数据；同一幂等键不会重复创建；
- [ ] 大文件异步显示进度，可取消，错误可分页下载；
- [ ] JSON/GEDCOM 导出后重新导入，核心成员和关系数量/语义一致；
- [ ] 敏感字段和媒体默认不导出，授权后才可选择；下载链接短时、绑定用户、过期失效；
- [ ] 导出 ZIP 有 manifest、schema 版本和哈希；生成文件按期清理；所有导出写审计。

## 10. 持久化、备份与恢复

- [ ] `backup.ps1` 不在脚本或命令参数硬编码密码，生成 SQL、uploads 压缩包和清单；
- [ ] 备份可计算 SHA-256、加密并复制离机；失败时返回非成功结果且不把残缺备份标记成功；
- [ ] 在新环境按文档恢复数据库和 uploads，服务恢复 healthy；
- [ ] 恢复后抽查用户、家谱、关系、附件、导入导出和审计，数量及哈希符合基线；
- [ ] 恢复演练满足约定 RPO/RTO，并形成记录。

## 11. 安全与运维

- [ ] 生产仅 HTTPS，HTTP 跳转，TLS 版本/证书有效；CORS 仅允许实际来源；
- [ ] 数据库不暴露公网，后端调试端口仅 loopback；安全响应头存在；
- [ ] SQL 注入、XSS、CSRF（如 Cookie 认证）、SSRF、对象越权和暴力登录测试通过；
- [ ] 密码强哈希，令牌/密码/连接串/证件号不进入日志或前端包；
- [ ] 依赖和镜像扫描无未接受的高危漏洞，镜像版本可追溯；
- [ ] 日常健康检查、容量监控、日志轮转、告警、维护窗口和事件响应流程可执行；
- [ ] OCR 外发审批、数据最小化、留存删除和供应商协议已落实（若启用）。

## 12. 性能与兼容性

- [ ] 约定数据规模下家谱列表、成员搜索和四层树达到项目 SLA；
- [ ] 并发编辑和异步任务不会耗尽数据库连接或工作线程；
- [ ] 最新两个主要版本的 Chrome/Edge 可完成所有主流程；
- [ ] 移动/窄屏至少可完成查看、搜索和基本编辑；
- [ ] 网络中断、后端重启、Provider 超时后有可理解提示，重试不会重复写入。

## 13. 验收结论

所有阻断级和高风险项必须通过。未通过项记录编号、影响、责任人、修复版本和复测日期；安全、权限、备份恢复、默认 OCR 不外发任一项失败均不得上线。最终由业务、研发、测试、运维和安全负责人共同签字确认。
